    How LLM-GC works

    Every request your app makes carries the whole conversation again, so the prompt grows with every message. LLM-GC is a garbage collector for that conversation: it keeps the prompt from growing without limit, and shows exactly what the model can still see. Numbers in this colour are your proxy's settings.

    When a cut happens

    1. After every reply, LLM-GC runs a pass (on screen, a check). Most passes change nothing.
    2. The newest … messages always stay in the young generation. Messages of … tokens or fewer are too short to compact: a collection keeps them whole.
    3. Once the older messages to be summarised or archived reach … tokens, the check makes a collection (a cut in the code) and moves them all at once. Changing the recap rarely keeps the provider's prompt cache working.
    4. A cut that would make the prompt bigger is skipped. Run GC now cuts at once, ignoring the token minimum but never that rule.

    What to watch

    1. Out of view: a message's facts were stored, but none made it into the recap, so the model sees nothing of it.
    2. An excerpt marked ✂: the recap carries only its start.
    3. A yellow banner: a move a collection planned did not happen, for example a summary request that failed. Nothing is lost; the prompt is just bigger than planned.
