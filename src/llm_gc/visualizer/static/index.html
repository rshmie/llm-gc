How LLM-GC works

Every request your app makes carries the whole conversation again, so the prompt grows with every message. LLM-GC is a garbage collector for that conversation: it keeps the prompt from growing without limit, and shows exactly what the model can still see. Numbers in this colour are your proxy's settings.

When a collection happens

  1. After every reply, LLM-GC runs a pass (on screen, a check). Most passes change nothing.
  2. The newest … messages always stay in the young generation. An exchange too short for its summary or opening line to be any smaller is kept word for word: a level is used only when it is cheaper.
  3. Once the older messages to be compacted or archived reach … tokens, the check makes a collection (a cut in the code) and moves them all at once. Changing the recap rarely keeps the provider's prompt cache working.
  4. A collection that would make the prompt bigger is skipped. Run GC now collects at once, ignoring the token minimum but never that rule.

What to watch

  1. Out of view: the recap reached its budget with every exchange already at its least detail, so the oldest were folded behind one line. The model knows they exist, not what was said. An ordinary conversation never gets there.
  2. A dot on a message: it changes form at the next collection, in the colour it will become. Earlier exchanges move too: up when the conversation comes back to them, down when it has moved on.
  3. Search says whether the model still receives the words you type, and if not, what it reads instead.
  4. A yellow banner: something to look at, such as exchanges out of view, or part of a collection that fell short (a summary request that failed, say). Each says what the model gets instead; nothing is lost. Dismiss one with × and it stays hidden until there is more of it.
